## ⚖️ 8-Hour Hackathon Reality Check: What's In vs. What's Out

To deliver a **flawless, winning MVP in 8 hours with 3 AIML students**, stick strictly to high-leverage Python tools:

### ✅ IN-SCOPE (High Impact, Fast Execution, Zero Fluff)
* **Pydantic v2 IR Schema**: Strict schema for nodes, edges, permissions, and conditions.
* **NetworkX Symbolic Graph Engine**: Cycle detection (`nx.is_directed_acyclic_graph`), topological ordering, and path reachability.
* **Semantic Ambiguity Detector**: Embeddings/keyword heuristics that catch missing numeric bounds and vague adjectives.
* **Adversarial Attack Suite**: 5+ pre-coded attack strategies with automated pass/block assertions.
* **Explainable Counterexample Generator**: Structured JSON diff showing the exact broken invariant and path.
* **Interactive Streamlit UI**: 3-panel reactive dashboard (Input & Graph Visualizer, Attack & Chaos Console, Execution & Proof Log).
* **Sample Policy Bank**: Instant 1-click presets for live judging (Procurement, IT Access, Expense Reimbursement).
* **Proof-of-Verification (PCW) Certificate**: SHA256-signed JSON report download.

### ❌ OUT-OF-SCOPE (Avoid Time Sink Traps)
* 🚫 Heavy relational databases (PostgreSQL/MySQL daemon setup) $\to$ **Use in-memory state + SQLite/JSON files**.
* 🚫 Microservices / Docker-compose / Kubernetes $\to$ **Single Streamlit monorepo**.
* 🚫 Custom LLM Fine-tuning $\to$ **Gemini 1.5 Flash Structured JSON mode + offline fallback mocks**.
* 🚫 Complex Frontend Frameworks (React/Vue/CSS) $\to$ **Pure Python Streamlit components**.

### 🧑‍💻 TRACK 1: DEV A (AI / NLP, Schema & Ambiguity Firewall)
> **Goal:** Take raw natural language and produce clean, validated, ambiguity-checked `WorkflowIR`.  
> **Primary Directory:** `compiler/`  
> **Key Deliverable:** `parse_policy()` & `check_ambiguity()`

- [ ] **1. Define Pydantic Schema (`compiler/ir.py`)**:
  - Create `StepNode` (id, action, role, condition, is_required).
  - Create `WorkflowIR` (workflow_id, name, trigger, steps, rbac_rules).
  - Add JSON serialization/deserialization methods.
- [ ] **2. Build Semantic Ambiguity Firewall (`compiler/ambiguity.py`)**:
  - Implement heuristic & embedding keyword scanner for unquantified terms (`"large"`, `"urgent"`, `"senior"`, `"soon"`).
  - Return clean structured dictionary with `is_ambiguous`, `warnings`, and suggested fixes.
- [ ] **3. Implement LLM Policy Parser (`compiler/parser.py`)**:
  - Write Gemini 1.5 Flash / LiteLLM prompt with structured Pydantic schema enforcement.
  - Add **Fail-Safe Offline Mode**: If no API key or network down, load corresponding JSON from `policies/`.
- [ ] **4. Build RBAC Matrix (`compiler/authorization.py`)**:
  - Define dictionary of valid roles (`Employee`, `Manager`, `Finance_Director`, `Admin`) and their permitted actions.
- [ ] **5. Unit Tests (`tests/test_parser.py`)**:
  - Add PyTest assertions verifying that valid text parses and ambiguous text triggers warnings.

---

### 🧑‍💻 TRACK 2: DEV B (Graph AI, Symbolic Verifier & Attack Simulator)
> **Goal:** Validate graph theory invariants and actively try to break workflows with adversarial mutations.  
> **Primary Directory:** `security/` & `compiler/graph_validator.py`  
> **Key Deliverable:** `verify_workflow()`, `run_attack_suite()`, & `counterexample.py`

- [ ] **1. Build NetworkX Graph Engine (`compiler/graph_validator.py`)**:
  - Convert `WorkflowIR.steps` into a `networkx.DiGraph`.
  - Check acyclicity using `nx.is_directed_acyclic_graph(G)` (detect cycles & deadlocks).
  - Check reachability from `START` node to `END` node (`nx.has_path`).
- [ ] **2. Build Deterministic Verifier (`compiler/verifier.py`)**:
  - Validate that mandatory guards (e.g. Finance Approval for $> ₹50k$) cannot be skipped.
  - Validate role assignments against `compiler/authorization.py`.
- [ ] **3. Implement 6-Vector Attack Simulator (`security/attack_simulator.py`)**:
  - ⚔️ *Attack 1 (Approval Bypass)*: Programmatically delete approval step and assert verifier catches it.
  - ⚔️ *Attack 2 (Role Escalation)*: Change `Finance_Director` to `Junior_Employee` and assert block.
  - ⚔️ *Attack 3 (Step Pruning)*: Remove verification prerequisites (e.g., skip vendor check).
  - ⚔️ *Attack 4 (Threshold Tampering)*: Mutate condition threshold ($₹50,000 \to ₹5,000$).
  - ⚔️ *Attack 5 (Cycle Injection)*: Add cyclical edge (`Approval -> Budget -> Approval`) and assert cycle error.
  - ⚔️ *Attack 6 (Unauthorized Exfiltration)*: Insert unapproved external API step.
- [ ] **4. Build Explainable Counterexample Engine (`security/counterexample.py`)**:
  - Generate clear, human-readable root-cause explanations showing the exact violating path.
- [ ] **5. Unit Tests (`tests/test_attacks.py`)**:
  - Assert that all 6 attacks are successfully blocked on valid workflows.

---

### 🧑‍💻 TRACK 3: DEV C (Streamlit Dashboard, Execution Engine & Demo)
> **Goal:** Create the visual UI, interactive graph rendering, mock execution runner, and judge scenarios.  
> **Primary Directory:** `app.py`, `executor/`, & `policies/`  
> **Key Deliverable:** Interactive Streamlit App, `execute_workflow()`, & `generate_proof_certificate()`

- [ ] **1. Create Streamlit Layout (`app.py`)**:
  - Configure page with dark theme, header badges, and metric cards (`Passed`, `Attacks Blocked`, `Compile Time`).
  - **Left Column**: Policy Input Text Area + 4 Preset Scenario Buttons.
  - **Center Column**: Interactive Graph Visualization + Verification Pass/Fail Status Box.
  - **Right Column**: Chaos Attack Console (live attack triggers) + Step Execution Log Terminal.
- [ ] **2. Graph Visualizer Component**:
  - Use `pyvis` or `streamlit.graphviz_chart` to render the workflow DAG with color coding:
    - 🟢 Green = Verified Safe Node
    - 🔴 Red = Attacked / Violating Node
    - 🟡 Yellow = Conditional / Guard Node
- [ ] **3. Step Execution Engine (`executor/engine.py`)**:
  - Deterministic state machine simulating execution of verified workflow with timestamped action logs.
- [ ] **4. Proof-Carrying Certificate (`executor/proof.py`)**:
  - Generate cryptographic SHA-256 hash of `(Policy + IR + VerificationReport)`.
  - Provide a one-click **"Download Verification Certificate (JSON)"** button.
- [ ] **5. Prepare 4 Preset Judge Scenarios (`policies/*.json`)**:
  - Scenario A: Valid Procurement (Full Pass & Proof)
  - Scenario B: Ambiguous Expense (Firewall Block)
  - Scenario C: Role Escalation (RBAC Block)
  - Scenario D: Adversarial Attack Suite (6/6 Defenses shown live)
- [ ] **6. Final Integration & Fail-Safe Test**:
  - Connect Dev A's parser and Dev B's verifier into `app.py`.
